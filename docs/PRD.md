# PicoShare 产品需求文档

| 项 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-10-02 |
| 状态 | 已与客户确认，作为设计与验收依据 |
| 适用范围 | 管理端 Web 界面、访客上传页、第三方图床工具接入通道 |

---

## 1. 产品概述

### 1.1 一句话定位

**一个自托管的轻量文件与图片分享服务**，部署在 Cloudflare 上，用一个访问密钥保护管理界面，兼顾三种用途：个人文件仓库、图床、限时收集他人文件。

### 1.2 目标用户

单个技术人员或小团队的自建部署者。全站只有一个共享密钥，不区分账号与角色——产品假设使用者彼此信任，密钥的职责是"防止被外人扫到"，而不是"在多人之间分配权限"。

### 1.3 核心使用场景

| 编号 | 场景 | 描述 | 主要入口 |
|---|---|---|---|
| S1 | **个人文件仓库** | 当作私人网盘长期存放文件，需要分类、搜索、批量清理 | 文件列表、文件详情 |
| S2 | **图床 / 截图分享** | 上传图片后立刻拿到可直接粘贴到文档、帖子、博客的链接 | 图片模式、图床工具接入 |
| S3 | **限时收集他人文件** | 给同事、客户开一个有时限、有配额的临时上传口子 | 访客链接 |
| S4 | **长期托管的图床素材** | 图片发出去之后长期可访问，需要能替换内容但保留历史 | 文件详情、历史版本 |
| S5 | **了解链接是否被传播** | 想知道某个文件是不是被别人到处转发、爬取 | 下载情况 |

S1 与 S4 说明产品**不是只做临时分享**。文件在多数情况下长期保存，有效期是可选的约束而非默认行为；过期能力是为"临时分享"和"控制存储增长"准备的，不是产品主轴。

### 1.4 产品原则

1. **拿到链接就能用。** 任何分享出去的链接都不需要对方登录、不需要额外授权，链接本身即凭证。
2. **上传后立即可用。** 上传完成的瞬间就返回可复制的链接，不需要二次配置。
3. **配额在源头限制。** 访客上传的限制在服务端强制执行，前端提示与实际执行永远一致。
4. **过期是文件的属性。** 有效期跟随文件本身，而不是跟随某条访问路径，任何入口都会遵守。
5. **不做多用户。** 不引入账号体系、分享权限、协作评论。

## 2. 范围界定

### 2.1 本期范围

- 密钥登录的管理界面
- 文件上传（选择、拖拽、粘贴文本）与图片上传（额外支持粘贴截图）
- 面向第三方图床工具的上传通道
- 文件列表、搜索、分页、批量删除
- 文件详情、元数据编辑、内容替换与历史版本
- 全局与单文件的有效期管理
- 访客链接的创建、配额、上传与删除
- 下载次数与来源查看
- 分享链接的访问体验（断点续传、浏览器缓存、文件名）
- 自动化的过期清理

### 2.2 明确不做

| 不做的事 | 原因 |
|---|---|
| 多用户账号体系 | 使用场景是自建单人服务，引入账号只会增加部署负担 |
| 分享密码、有效期之外的访问控制 | 链接本身就是凭证，再叠加一层会让分享变得麻烦 |
| 文件夹 / 目录结构 | 使用方式是搜索 + 列表，目录树解决不了实际问题 |
| 在线编辑、在线预览 Office 文档 | 需要引入文档渲染服务，与"轻量"定位冲突 |
| 跨设备同步客户端 | Web 界面已覆盖跨设备访问 |
| 付费、套餐、计量计费 | 无商业化需求 |

## 3. 功能需求

需求编号规则：`FR-<模块字母>-<序号>`。

---

### 3.1 访问控制（FR-A）

#### FR-A-1 单一访问密钥

- 系统使用一个全局共享密钥保护管理界面。
- 未提供或提供错误密钥时，管理界面与所有管理功能均不可访问。
- 不存在注册、找回、多账号等流程。

**验收要点**：错误密钥无法进入管理界面，也无法通过任何方式读取或修改文件数据。

#### FR-A-2 密钥的保存

- 密钥保存在使用者自己的浏览器本地，关闭浏览器后再次打开仍然有效。
- 提供"退出登录"，退出后清除本地密钥并回到登录页。
- 页面明确告知密钥仅保存在本地浏览器。

#### FR-A-3 密钥未配置时的行为

- 部署时若密钥为空，所有受保护接口（含登录）一律返回 `401`，不做任何默认回落。
- 不得以"默认密钥"的形式对外提供服务。
- 该约束由部署文档承担，运行时不做启动检查。

#### FR-A-4 未授权访问的频率限制

- 密钥校验失败的请求按访问方地址计数，同一地址在 5 分钟内失败超过 20 次后，短期内一律拒绝并提示稍后再试。
- 目的是抬高暴力猜测的成本，而非提供强防护。

#### FR-A-5 防暴力破解的分工

- **主要防护由 Cloudflare WAF 规则承担**，包括登录接口的限速与访问地域限制。
- 应用自身保留的频率限制仅作为兜底，配置 WAF 后不要求调高应用层阈值。

---

### 3.2 文件上传（FR-B）

#### FR-B-1 上传入口

- 上传页提供「文件」与「图片」两种模式。
- 文件模式：支持点击选择、拖拽到页面任意位置、多选。
- 图片模式：在文件模式基础上，额外支持在页面任意位置按 `Ctrl+V` 直接粘贴截图，并自动识别图片格式与扩展名。
- 两种模式互相独立，切换模式会清空已选内容，避免误传。

#### FR-B-2 粘贴文本

- 支持直接粘贴文本内容，文本以独立文件形式保存，文件名自动生成。
- 单次粘贴文本上限 1 MB。

#### FR-B-3 单次上传数量

- 一次最多上传 20 个文件。
- 超过上限时提示"一次最多上传 20 个文件"，不静默丢弃。

#### FR-B-4 单文件大小

- 单个文件上限 100 MB。
- 达到 100 MB 的文件自动切换为分片上传，界面上显示实时进度百分比。
- 超过上限的非分片上传请求要被明确拒绝并提示原因，不允许因体积超限而报出难以理解的错误。

#### FR-B-5 上传选项

上传时可为整批文件设置：

| 选项 | 说明 |
|---|---|
| 备注 | 可选，仅自己可见，最长 1000 字符 |
| 有效期 | 永久保存，或在 N 天后过期 |

- 有效期的默认值取自全局设置（见 FR-E-1），打开上传页时已按全局设置预选。
- 天数由一个数字输入框填写（1 ~ 3650 天），不提供快捷档位列表：一个下拉框装不下用户想要的
  数字，而快捷列表会在用户正在输入的数字下方再摆一份数字。
- 「永久保存」用勾选框表达。勾选时天数输入框才出现，取消勾选会保留已填的天数而不是清空，
  以免删到一半就把设置改掉。

#### FR-B-6 上传结果

- 上传完成后集中展示结果列表，每项包含文件名与分享链接。
- 提供「复制全部链接」，一次复制所有链接。
- 图片模式下每一项额外提供「复制直链 / Markdown / HTML / BBCode」四种形式。

#### FR-B-7 大文件上传中断

- 分片上传过程中若网络中断，允许重新发起该文件的上传而不影响已完成的其他文件。
- 24 小时未完成的分片上传会被自动清理，不长期占用存储。

### 3.3 图片上传与图床接入（FR-C）

#### FR-C-1 相同图片秒传

- 上传图片时，若服务中已存在**内容完全相同**的图片，则复用已存储的内容，不再重复存储。
- **不复用原有链接**：本次上传会得到自己的分享链接，以免把为第一位收件人准备的链接交给第二个人。
- 仅对图片生效；非图片内容不做此优化。
- 内容相同的判定基于文件内容的校验值，同时要求文件大小一致。
- 超过 32 MB 的文件不参与秒传（避免为了计算校验值而长时间占用服务器内存）。

**验收要点**：重复上传同一张图片不会增加存储占用。

#### FR-C-2 秒传时的信息呈现

- 上传结果中，被复用的图片标注「已存在」。
- 明确提示：这些图片的**备注与有效期设置未生效**，因为复用的是原有文件的信息。
- 复制 Markdown 时，替代文字使用本次上传的文件名，而不是原有文件名。

#### FR-C-3 访客上传的去重范围

- 访客上传的去重**仅在同一个访客链接内部生效**。
- 不同访客链接之间不做去重，访客 A 上传过的图片不会被访客 B 复用。

**原因**：分享链接即凭证，跨链接复用会让访客拿到不属于自己的链接。

#### FR-C-4 面向图床工具的上传通道

为第三方上传工具（PicGo、ShareX、uPic 等）提供一个上传地址，它接受**两种请求格式**：

| 请求格式 | 谁在用 | 文件名从哪来 |
|---|---|---|
| 表单（`multipart/form-data`） | 浏览器、PicGo 及绝大多数图床工具 | 上传的表单字段 |
| 裸数据（请求体即文件本身） | 命令行脚本、只能发原始数据的工具 | 网址参数 |

- 两种格式返回**完全相同**的结果，区别只在请求怎么发。上传地址只有一个。
- 返回结果包含**可直接使用的绝对地址**，以及 Markdown、BBCode 两种引用形式，不含需要使用者自行拼接的相对路径。
- 服务部署在反向代理之后时，返回的地址必须可被公网访问，不得使用内部分发地址。

**关于 HTML 引用形式**：接口当前不返回它，需要者在自己的工具里拼 `<img src="地址">`。
网页界面上的「复制 HTML」按钮是在浏览器本地生成的，与接口无关。若后续有工具反馈需要，
再在返回结果里加一个字段即可。

#### FR-C-5 图床工具的鉴权方式

图床工具配置上可能受限，因此支持三种提供密钥的方式：

1. 请求头（推荐，密钥不出现在网址中）
2. 独立的密钥请求头
3. 把密钥放在网址参数里

**约束**：第三种方式**仅对上传地址开放**，其他所有功能一律只接受请求头方式。

**原因**：网址形式的密钥会出现在浏览器记录、代理日志与外部站点的访问来源中；上传是唯一"工具无法自定义请求头"而必须妥协的场景。**只开放一个地址**是有意的：允许的路径每多一条，密钥出现在网址里的机会就多一分。

#### FR-C-6 图片管理页

- 独立于文件列表，提供图片画廊视图。
- 画廊内可按文件名搜索。
- 点击图片进入大图查看，可左右切换、关闭，并可直接复制该图的各种引用形式。
- 图片在列表中延迟加载：只有滚动到可见位置时才加载，避免一次性加载大量原图。

### 3.4 文件浏览与管理（FR-D）

#### FR-D-1 文件列表

列表以表格呈现，每一项包含：

文件名、大小、当前版本号、上传时间、过期时间、下载次数、来源（本人上传 / 访客上传）。

- 默认按上传时间倒序，最新的在最前。
- 点击文件名进入文件详情。

#### FR-D-2 搜索

- 支持按文件名模糊搜索，输入即筛选。
- 搜索会同时作用于文件列表和图片列表。
- 搜索词超过 128 字符时截断处理。

#### FR-D-3 分页

- 每页默认 50 条，最多可调到 100 条。
- 列表底部显示剩余数量并提供「加载更多」，不清空已加载的内容。
- 搜索条件变化时清空已加载内容并重新开始。

#### FR-D-4 批量删除

- 列表支持勾选多个文件后一次性删除。
- 单次最多删除 100 个文件，超出时提示。
- 删除前必须二次确认，确认文案明确说明不可恢复。
- 批量操作完成后，若有正在查看的详情项被删除，自动退出查看。

#### FR-D-5 搜索与勾选的交互

- 切换搜索词时清空勾选状态。
- **原因**：旧结果集中的文件在筛选后已不可见，若保留勾选，一次批量删除会删掉使用者看不到的文件。

#### FR-D-6 文件详情

详情页展示：

- 基本信息：大小、版本号、上传时间、更新时间、过期时间（永久保存时显示"永久"）、下载次数
- 内容校验值（SHA-256），可一键复制；大文件可能不提供，此时显示"未计算"
- 预览：图片、PDF、纯文本、音频、视频等安全类型可直接在页面内预览
- 编辑表单（见 FR-D-7）
- 历史版本（见 3.6）
- 下载情况（见 3.8）

#### FR-D-7 编辑文件信息

可修改：**文件名**、**备注**、**是否设置过期时间及其天数**。

- 每次只修改本次提交的字段，未提交的字段保持原值。
- 文件名最长 255 字符，备注最长 1000 字符，过期天数上限 3650 天。
- 设置过期天数时，天数从保存当天起算。

**原因**：部分更新保证脚本或页面只想改一个字段时，不会意外清空其它信息。

#### FR-D-8 删除文件

- 详情页提供删除操作，需二次确认。
- 删除后分享链接立即失效。
- 删除文件的**同时删除其历史版本**，不保留任何副本。

### 3.5 有效期管理（FR-E）

#### FR-E-1 全局默认设置

设置页提供两项全局配置：

| 配置 | 说明 | 默认值 |
|---|---|---|
| 新文件永久保存 | 勾选后新上传的文件不设过期时间 | 勾选 |
| 默认过期天数 | 未勾选永久保存时生效，1 ~ 3650 天 | 30 |

- 设置保存后立即对之后的所有上传生效，不影响已存在的文件。
- 勾选「永久保存」时，默认天数输入框置灰但保留已有数值。

#### FR-E-2 有效期的优先级

1. 上传时手动指定的天数
2. 全局默认天数（未勾选永久保存时）
3. 永久保存

#### FR-E-3 访客上传的有效期

- 访客上传的文件，其有效期由访客链接的「文件保存天数」决定，与全局设置无关。
- 访客链接未设置保存天数时，访客上传的文件永久保存。

#### FR-E-4 访客链接删除后的文件有效期（**已确认**）

- **删除访客链接时，该链接下已上传的文件全部保留，不随链接一起删除。**
- 这些文件**继续按原定的保存天数到期，到期后自动删除**；原本设置为永久保存的则继续永久保留。
- 这些文件会重新出现在主文件列表中，可被搜索、编辑、删除。
- 链接的失效日期只影响"还能不能继续上传"，不影响已上传文件的存续。

#### FR-E-5 过期的执行

- 过期文件通过系统自动清理删除，清理周期为每小时一次。
- 即使自动清理尚未运行，任何一次访问过期文件的操作也会立即触发删除并提示文件已过期。
- 清理能力有并发与资源上限，因此**大量文件同时过期时，实际删除时间可能延后到后续周期**；但任何人访问都不会拿到已过期文件的内容。

#### FR-E-6 未完成上传的清理

- 大文件分片上传若在 24 小时内未完成，其已上传的部分会被自动清理。

---

### 3.6 历史版本（FR-F）

> 客户已确认该功能在日常使用中会被使用，纳入本期范围。

#### FR-F-1 替换内容

- 详情页提供「替换文件」，选择新文件即可替换当前内容，**文件名保持不变**。
- 替换过程支持大文件分片上传并显示进度。

#### FR-F-2 保留历史

- 替换前的旧内容作为历史版本保留，可在详情页查看与下载。
- 每次替换使版本号加 1，列表与详情中始终展示当前版本号。

#### FR-F-3 并发冲突提示

- 若在替换期间该文件已被其它操作更新（例如换了内容或改了版本），本次替换被拒绝并提示冲突，不覆盖他人的结果。

#### FR-F-4 历史版本列表

每个历史版本展示：版本号、大小、保存时间、内容校验值。

- 每个历史版本可单独下载。
- 每个历史版本可单独删除，删除前二次确认。
- **当前版本不可删除。**

#### FR-F-5 版本与占用的关系

- 存储占用统计包含历史版本。
- 删除历史版本会立即释放对应空间。

### 3.7 访客链接（FR-G）

#### FR-G-1 创建访客链接

创建时可设置以下五项：

| 项目 | 说明 | 未填写时 |
|---|---|---|
| 备注 | 仅创建者可见的私密备注，最长 120 字符 | 无备注 |
| 单文件大小上限 | 单位 MB | 64 MB |
| 文件保存天数 | 访客上传的文件多久后删除 | 永久保存 |
| 上传次数上限 | 该链接累计可上传的文件个数 | 200 个 |
| 链接失效日期 | 到期后访客无法再上传 | 永不过期 |

**关于默认值**：未填写的大小与次数上限**不是"无限制"**，而是给出一个明确的保守上限。原因是访客上传在一次请求内可包含多个文件，若真按无限制处理，单个访客一次就能占满全部存储。

#### FR-G-2 访客链接列表

每条链接展示：备注（或"未命名链接"）、各项限制摘要、已上传文件数、已用次数、链接地址、失效日期。已失效的链接有明确标记。

- 列表按创建时间倒序。
- 提供一键复制链接地址。
- 提供删除操作。

#### FR-G-3 访客上传页

访客打开链接后看到：

- 上传表单（文件、粘贴文本、备注）
- 各项限制的明示：单文件大小上限、剩余上传次数、文件保存天数、单次最多文件数、链接失效日期
- 上传进度
- 无需登录

- 访客**看不到**创建者填写的备注。
- 页面标题固定为"访客上传"，不包含创建者的备注内容。

#### FR-G-4 配额耗尽

- 剩余次数为 0 时，访客页显示"该链接的上传次数已用完，请联系链接创建者"，并隐藏上传表单。
- 次数用尽后，即使刷新页面也不可继续上传。

#### FR-G-5 并发下的配额准确性

- 多个访客同时上传时，总次数不得超过设置的上限。
- 上传过程中失败的请求会**归还已占用的次数**，不出现"次数被扣但文件没上传成功"的情况。
- 上传成功后，访客页立即显示更新后的剩余次数，无需刷新。

#### FR-G-6 访客上传的结果

- 上传成功后立即列出每个文件的分享链接，可单个复制。
- 图片额外提供 Markdown、BBCode 引用形式的复制。
- 若有图片因内容重复被复用，页面说明"N 个为已存在的相同图片，复用了已存储的内容"。

#### FR-G-7 删除访客链接

- 删除前二次确认，文案明确说明"已上传的文件会保留"。
- 删除后链接立即失效，访客无法再访问上传页。
- 已上传文件按 FR-E-4 处理。

### 3.8 下载情况（FR-H）

> 客户已确认目标是**了解链接是否被传播或爬取**，而非合规审计。据此确定以下设计。

#### FR-H-1 核心视角：有多少人来过

- 每个文件在列表与详情中显示**总下载次数**。
- 详情页的下载情况区域提供「按访问地址去重」开关，**默认开启**。
- 默认视图下，同一访问地址的多次下载合并为一条，展示该地址的最后一次下载时间与访问次数。

**设计理由**：使用者真正关心的是"多少人看过了、有没有在到处传"，而不是逐条日志。按地址去重的默认视图直接回答了这个问题。

#### FR-H-2 明细视图

关闭「按访问地址去重」后展示逐条记录：下载时间、访问地址、客户端信息。

- 单个文件最多返回最近 200 条记录。
- 该区域加载失败时不阻断详情页其它内容。

#### FR-H-3 隐私

- 下载记录**仅创建者可见**，访客上传页与任何分享链接均不暴露下载信息。
- 访客的访问地址与客户端信息属于个人数据，保留 90 天后自动清除。

#### FR-H-4 不计入下载的情况

以下操作**不计入**下载次数：

- 浏览器发起的文件大小探测（不取内容的那种请求）
- 使用者自己在管理界面里的预览

**设计理由**：若计入，图片画廊的缩略图加载会让次数虚高，无法反映真实传播情况。

### 3.9 分享与访问体验（FR-I）

#### FR-I-1 两种链接形式

| 形式 | 用途 |
|---|---|
| 短链接 | 通用，适合直接发送 |
| 带文件名的图片链接 | 展示更友好，文件名对阅读者可见 |

- 两种链接指向同一份内容，权限完全一致：拿到即可访问，无需登录。
- 详情页与上传结果中提供一键复制。

#### FR-I-2 图片链接的文件名

- 带文件名的图片链接在被访问时，若其中的文件名与实际不符，自动跳转到正确地址。
- **原因**：文件名是给人看的，改过文件名的旧链接应继续可用。

#### FR-I-3 大文件播放与下载

- 视频、音频支持拖动进度播放，不从头开始重新下载。
- 其它大文件支持断点续传。
- 浏览器重复访问同一文件时直接使用本地缓存，不重复下载。

#### FR-I-4 链接即凭证

- 分享链接是公开的，任何持有链接的人都能访问，不做额外校验。
- 链接标识必须使用不可猜测的随机方式生成，不允许缩短或使用可预测的规则。
- 因此**分享链接一旦泄露即视为已授权**，敏感内容不应使用本产品长期存放。

#### FR-I-5 内容呈现方式

- 图片、视频、音频、PDF、纯文本：浏览器直接打开。
- 其它类型：强制下载。
- **以下类型一律强制下载，不在浏览器中渲染**：SVG、HTML 等可能携带可执行内容的格式。
- 浏览器不得猜测文件内容的真实类型。
- 图片类内容允许浏览器缓存较长时间，其它内容每次访问都要向服务器确认是否变化。

#### FR-I-6 链接地址的正确性

- 生成对外链接时使用对外可访问的域名。
- 当部署在会转发原始域名的代理之后时，不得直接采用请求中的域名来拼接链接。
- **原因**：分享链接会被粘贴进 README、帖子等长期可见的位置；若被恶意构造的域名影响，使用者会发布出指向错误站点的链接。

#### FR-I-7 分享链接的创建与撤销

- 分享链接是一条独立记录，不是文件的属性。**一个文件可以同时存在多条链接**，每条可以有不同的备注与有效期。
- 撤销一条链接**不会删除文件**，文件随时可以再创建一条新链接。
- 链接的有效期只作用于这条链接，不影响文件本身可以保留多久；全局「永久保存」设置也不改变已创建链接的有效期。
- **只有图片在上传时会自动获得一条分享链接。**文件不自动创建——发一条链接是一个决定，不是一个默认结果——
  由主人在详情页或列表页主动创建。
- 替换文件的内容时，已经发出去的链接继续有效，返回同一个链接标识，不会因为文件变大而换一条。
- 入口只有两个：文件列表的每一行，和文件详情页。按钮都叫「分享管理」，点击后弹出该文件的全部链接，
  每条链接各有自己的「复制」。
- **按钮不叫「复制链接」**：一条文件有两条以上链接时，「复制链接」没有指代对象。与其让服务端替用户猜
  复制哪一条，不如多一次点击换来确定性。
- 列表页不展示链接状态，因此关闭弹窗后不刷新列表；详情页有一处摘要（还剩几条可用），所以关闭弹窗后会重读。
- 被撤销的链接立即失效（404）；自然过期的链接返回 410，并提示文件已过期。两者都不删除文件。

### 3.10 系统信息与自动维护（FR-J）

#### FR-J-1 系统信息

设置页展示：存储总占用、文件总数、访客链接数、累计下载次数。

- 存储占用包含历史版本。
- 页面标注数据获取时间。

#### FR-J-2 自动维护

系统每小时自动执行一次维护，内容包括：

1. 删除已过期的文件及其历史版本
2. 清理超过 24 小时未完成的分片上传
3. 清理超过 90 天的下载记录

- 三项任务相互独立，其中一项失败不影响其余两项。
- 除定时执行外，每次有请求进来时也会顺带触发一次维护，保证长时间无访问的情况下过期文件也会被清理。
- 维护在后台进行，不阻塞使用者的正常请求。

## 4. 全局体验要求

### 4.1 界面语言

- 界面文案统一使用简体中文，不提供语言切换。

### 4.2 提示与错误

- 所有面向使用者的提示使用中文，且说明**具体原因与可采取的下一步操作**，例如"文件 x.png 超过上限 20MB"，而不是"请求失败"。
- 前端提示的限制值必须与服务端实际执行的限制一致。任何情况下不得出现界面显示"大小不限"而服务端仍在拦截的情况。
- 操作成功后的结果应有明确反馈（提示条、状态变化），不依赖使用者自行观察。
- 破坏性操作（删除文件、删除历史版本、删除访客链接、批量删除）必须二次确认，且确认文案说明后果。

### 4.3 容量与限制一览

| 项目 | 限制 |
|---|---|
| 单次上传文件数 | 20 个 |
| 单文件大小 | 100 MB（达到即自动分片） |
| 粘贴文本大小 | 1 MB |
| 文件名长度 | 255 字符 |
| 备注长度 | 1000 字符 |
| 访客链接备注长度 | 120 字符 |
| 有效期天数 | 1 ~ 3650 天 |
| 列表每页条数 | 默认 50，最多 100 |
| 单次批量删除 | 100 个文件 |
| 单文件下载记录 | 最近 200 条 |
| 搜索词长度 | 128 字符 |
| 下载记录保留 | 90 天 |
| 未完成分片上传保留 | 24 小时 |
| 参与秒传的图片 | 32 MB 以内 |
| 访客链接默认单文件上限 | 64 MB |
| 访客链接默认次数上限 | 200 个 |
| 访客单次上传总量 | 64 MB |

### 4.4 安全底线

1. 分享链接的标识不可猜测，不使用可预测的生成规则，不允许为了美观而缩短。
2. 访客上传的配额在服务端强制执行，不依赖前端配合。
3. 频率限制只信任平台提供的真实访问地址，不使用可被伪造的转发信息。
4. 上传内容在浏览器中的呈现方式由服务端决定，不采信客户端声明。
5. **访问频率的主要防护由 Cloudflare WAF 承担**，应用层的频率限制是辅助手段，二者并存。

## 5. 已知限制

以下限制已知并接受，不在本期解决：

| 限制 | 影响 | 说明 |
|---|---|---|
| 自动清理有单次数量上限 | 大量文件同时到期时，实际删除时间可能延后到后续周期 | 受服务器单次处理能力约束；但过期文件在任何入口都不会被读到 |
| 画廊缩略图加载原图 | 图片较多时浏览器的流量与内存消耗较高 | 当前无缩略图能力，靠"滚动到才加载"缓解 |
| 大文件不参与秒传 | 超过 32 MB 的图片不享受相同图片秒传 | 避免为计算校验值长时间占用服务器内存 |
| 访客链接的备注对访客不可见 | 访客无法得知这个链接是谁创建的 | 备注属于创建者的私密信息 |
| 单用户模型 | 无法多人分权管理 | 本产品定位为自建单人服务 |

## 6. 后续规划

按优先级排列，均不改变现有功能定位：

1. **图片缩略图** — 为画廊提供小尺寸预览，降低流量与内存消耗。
2. **清理效率提升** — 支持一轮清理更多文件，缩短大量文件集中到期时的滞留时间。
3. **访客链接的用量与剩余次数概览** — 在访客链接列表中直接查看访问与上传趋势。
4. **文件备注的检索** — 目前搜索只覆盖文件名，备注内容不参与检索。
